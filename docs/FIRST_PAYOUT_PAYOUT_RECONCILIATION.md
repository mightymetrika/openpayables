## Evidence contract

The read-only operator command `npm run live:payout -- status APPROVAL_UUID` reports the transfer and recorded trace. `npm run live:payout -- reconcile APPROVAL_UUID po_ID` uses the same exact payer's restricted LIVE read key, dedicated LIVE database and explicit `YES_READ_ONLY` confirmation. It requires a durable attempt and verified transfer observation. It retrieves and validates the exact transfer again, including amount, destination, approval metadata and group, LIVE mode and destination payment ID. Under `Stripe-Account` set to the frozen recipient account it retrieves the specified payout and queries `/v1/balance_transactions` with the `payout` filter alone when reconciliation is completed. It matches `source` locally, ignoring the payout debit and unrelated transactions. Actual sandbox inspection on 2026-11-24 returned HTTP 400 for the combined filters, then verified one exact destination-payment transaction for the existing 800-cent TEST transfer in a paid automatic payout using the payout-only query. The exact destination payment must be the source of a single available USD balance transaction with the approved gross amount and valid net/fee arithmetic. No inference from equal amounts, approximate timing, a payout alone, manual/instant payouts or incomplete membership. For this bounded pilot, a list with `has_more: true` fails closed; it requires manual review rather than accepting a partial page. The API contract and restricted permissions must be tested against an actual sandbox; mocks do not prove this integration works against Stripe.

Only standard automatic USD bank payouts with completed reconciliation are traceable. An aggregate payout can include other transactions, so its total is not the transfer amount or recipient net. Stripe-reported `paid` is not independent proof that a recipient received money in their bank; later failure can occur. A recorded failure/reversal overrides earlier paid observations, and a transfer reversal overrides payout status. If a matched payout subsequently fails, a fresh authenticated retrieval may reuse the earlier recorded membership. One matched payout per approval is a conservative pilot restriction; a retry/replacement payout requires manual incident review. No automatic resend, reversal, payout creation, or top-up. Recipient confirmation of bank receipt remains a separate real pilot acceptance requirement. `bankPayoutVerified` intentionally remains false; `payoutState` reports provider evidence only.

## Signed snapshot webhook listener

`npm run webhook:live-pilot` starts a loopback-only listener with a dedicated non-admin LIVE DB login, a restricted read-only key, exact expected payer, and separate secret variables `OPENPAYABLES_LIVE_PLATFORM_WEBHOOK_SECRET` and `OPENPAYABLES_LIVE_CONNECTED_WEBHOOK_SECRET`. The two routes `/stripe/live/platform` (platform account snapshot transfer events) and `/stripe/live/connected` (connected account snapshot payout events) require independently configured Stripe endpoint secrets and raw request bodies. Enable only transfer.created/updated/reversed and payout.created/updated/paid/failed/canceled/reconciliation_completed as appropriate. The signing timestamp must be within five minutes. TEST events and crossed account scopes are rejected. Signed event contents are routing hints, not proof of status: reconcile via authoritative GET and append immutable observations. Duplicate deliveries are harmless to the ledger; no raw event payload, credentials or banking details are retained. Unrelated events are ignored, no event can create a payment attempt, and failures return a retry response. If a payout precedes the transfer observation or membership is not yet available, use later reconciliation events or the read-only operator command. After one payout is matched, other payout IDs are not automatically attributed; inspect replacement payouts manually.

Do not expose a plain HTTP loopback listener directly. Operational acceptance must configure trusted HTTPS ingress with Stripe's documented IP restrictions, verify raw body preservation, signatures, correct account and endpoint scopes, retry/delivery behavior and bounded request handling. Reconciliation performs synchronous provider reads; test webhook response timing and manual recovery in a sandbox before release. Store keys and secrets in an operator secrets vault, never Git, chat or logs. Use separate sandbox/LIVE credentials and distinct endpoint signing secrets. Grant only the minimum read permissions needed for platform account/balance/transfers and connected-account payout and balance transactions. Dedicated LIVE DB provisioning and least-privilege grants are not performed by this patch. Hosted development roles cannot access the pilot ledger.
